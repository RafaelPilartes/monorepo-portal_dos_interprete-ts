# Step H8 — The service lifecycle and the suspension cascade

> Executed inline in continuous mode. Independent review at the end of the step.

**Goal:** after a request has interpreters: cancel (the whole request, or one place), mark as done from the end, confirm (by hand or by the clock), dispute and resolve; and a suspension cancels what has not started yet, in its own transaction.

**Spec:** `docs/plan/specs/service-lifecycle.md` (R-LIFE-01..07, criteria 1–5; criterion 6 closes in H11); `accounts-and-organizations.md` R-ACC-05 and criterion 5 (the requests part); D-21, D-22, D-90.

## Decisions (AD-037)
- Migration `0010-lifecycle.sql`: `booking.disputes`, one open per assignment (`disputes_one_open`, mapped to `DISPUTE_OPEN`).
- `99-lifecycle.sql`: `cancel_request` (through `cancel_whole_request`, also used by the suspension), `cancel_assignment`, `mark_delivered`, `confirm_delivery`, `auto_confirm_deliveries` (every 5 minutes), `open_dispute`, `resolve_dispute` (moderator, not a party), `on_account_suspended`, `on_organization_suspended`; views `directory.late_cancellations` (12 months, by `cancelled_by_role`) and `booking.dispute_details`.
- Late (D-22) is strict: `starts_at - now < cancellation_free_until_hours`; only accepted places; the team is never late.
- `refresh_request_status`: after the start a place no longer reopens (a dispute resolved as cancelled ends the request, R-LIFE-07); threads close on `completed`/`cancelled`.
- The screens read, never compute, the late flag and the confirmation deadline: `request_details.cancel_is_late` and `assignment_details.confirm_by` through `auth_helper` wrappers.

## Tasks
1. Database, the suspension calls in `identity.suspend_account` / `suspend_organization`, SQL assertions `0010-lifecycle.sql` (criteria 1–5, the forced-error rollback).
2. API: `POST /requests/:id/cancel`, `/assignments/:id/cancel|deliver|confirm|disputes`, `/admin/disputes/:id/resolve`; a DB test through the API.
3. Screens: requester detail (cancel with the late warning, confirm, dispute), interpreter detail (cancel participation, mark as done, dispute) and `/schedule`, admin `/requests` and `/requests/:id` with "Resolver" (replacing the mocks); notification texts.
4. Playwright `h8-lifecycle`: done → confirmed; dispute → resolved in admin; the late warning.
