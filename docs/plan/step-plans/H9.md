# Step H9 — Double-blind reviews

> Executed inline in continuous mode. Independent review at the end of the step.

**Goal:** after a completed service each side reviews the other once (1–5 stars, optional comment); a review stays hidden until both reviewed or `review_reveal_days` passed; a moderator hides one with a reason; the averages are views.

**Spec:** `docs/plan/specs/reviews.md` (R-REV-01..05, criteria 1–5); D-43, D-44; R-DIR-05.

## Decisions (AD-038)
- Migration `0011-reviews.sql`: `booking.reviews`, `UNIQUE (assignment_id, author_role)` mapped to `REVIEW_EXISTS`.
- `99b-reviews.sql`: `submit_review` (the second side reveals both in the same transaction), `reveal_reviews` (hourly), `hide_review` (moderator, audited), `review_requested` sent by a trigger when an assignment completes by any path; `auth_helper.can_view_requester_reviews` (D-44); views `booking.review_details`, `directory.interpreter_ratings`, `booking.requester_ratings`, `booking.reviews_to_do`.
- `directory.public_listing` reads the rating from the reviews (same rule as `interpreter_ratings`).

## Tasks
1. Database and SQL assertions `0011-reviews.sql` (criteria 1–5, the cancelled edge case).
2. API: `POST /assignments/:id/reviews`, `POST /admin/reviews/:id/hide`.
3. Screens: `/reviews` in both panels (to review, given, received), the form in the request detail, the requester's reviews for an invited interpreter, the rating and reviews on the interpreter profile, the account sheet in admin with "Esconder".
4. Playwright `h9-reviews`: both review and see at the same time; a moderator hides one.
