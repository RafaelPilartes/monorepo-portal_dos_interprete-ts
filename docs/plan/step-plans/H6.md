# Step H6 — Price negotiation

> Executed inline in continuous mode. Independent review at the end of the step.

**Goal:** in the chat of a direct request, the requester and the invited interpreter propose prices; one proposal open per thread; the other party accepts or rejects; an accepted proposal changes the price offered; only the interpreter's acceptance of the request fixes the price.

**Spec:** `docs/plan/specs/negotiation.md` (R-NEG-01..05, criteria 1–5); `docs/plan/data-model.md` §5 (`booking.proposals`); `docs/plan/api.md` §8.

## Decisions (AD-035)
- Migration `0008-proposals.sql`: `booking.proposals` with the partial unique index (one open per thread) and `previous_amount_aoa` (the price in force when proposed, for "era 15 000 Kz").
- `booking.make_proposal` voids the open proposal and inserts the new one; `booking.respond_proposal` checks PROPOSAL_NOT_OPEN and OWN_PROPOSAL; `booking.accept_assignment` voids the open proposals of the assignment (requests-direct criterion 5).
- Only the requester–interpreter threads in H6: the managed request's thread with the team arrives with H11; the open request (and criterion 5, "first to accept" without negotiation) with H7, where `open_negotiation` already refuses `first_accept`.
- The proposals are cards among the messages of `RequestChat`, read every 10 seconds like the messages (AD-034.6).

## Tasks
1. Database: migration, functions, view `booking.proposal_details`, policies, grants; SQL assertions `0008-proposals.sql`.
2. API: `POST /threads/:id/proposals`, `POST /proposals/:id/accept`, `/reject`; API test.
3. Chat: proposal cards, "Propor outro preço", Aceitar/Recusar, "A negociação está fechada."; Playwright `h6-negotiation`.
